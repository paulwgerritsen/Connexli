Fix RELD batch verification, add never-verified cleanup, and real Stripe payments

Part 1 — RELD (Paul, Sep 25):
- Root cause of the "Run RELD Audit" HTTP 422: the batch payload used the key
  "licensees"; RELD's documented request body is {"licenses":[{state,license_number}]}.
  Fixed, with sanitized diagnostics logged for every RELD call (never the key).
- Audit now sends every professional (no LIMIT), auto-chunks to RELD_BATCH_SIZE
  (default/max 100), matches results by state+number, isolates a record RELD
  rejects by splitting the chunk, skips malformed records up front, and reports
  per-record Verified / Failed verification / API error / Skipped. An outage or
  API error never downgrades a verified professional.
- New reld_first_verified_at (backfilled) marks anyone who ever passed.
- Admin → "Remove never-verified (test) accounts": lists only professionals who
  never passed RELD verification and were never admin-confirmed; exact warning
  text with live count, checkbox list, typed DELETE second confirmation, and a
  re-check of eligibility at execution time. Logged with the removed accounts.

Part 2 — Stripe payments:
- Hosted Stripe Checkout (test keys first) for the single $10 credit inside an
  opportunity and for bundles from the dashboard; prices come from server config
  (or STRIPE_PRICE_* Price IDs); billing address required; Stripe Tax gated by
  STRIPE_TAX_ENABLED; promotion codes allowed.
- Webhook /webhooks/stripe is the authoritative, signature-verified, idempotent
  fulfilment path (stripe_events table); the return page is a server-verified
  backup. Fulfilment claims the order row and writes the ledger in one
  transaction so a duplicate can never double-credit.
- Free proposals and paid credits are separate; the ledger records which
  proposal consumed a paid credit, balance_after, order/Stripe/proposal ids and
  admin reasons (PURCHASE, PROPOSAL_USED, FREE_PROPOSAL_USED, REFUND,
  ADMIN_CREDIT, ADMIN_DEBIT, PROMOTIONAL_CREDIT).
- Refund webhooks reverse only unused paid credits; a shortfall flags the order
  for admin review instead of driving a balance negative.
- Professional Purchase History (date, package, credits, amount, status, refund,
  receipt link; no Stripe ids). Admin Payments & revenue: totals, by billing
  state, by month, transactions with Stripe refs, flagged refunds, CSV export;
  per-professional Payment history and Credit history.
- render.yaml + README document every Stripe variable and the setup order.

Tests: test_v23.js (78 checks) against mock Stripe + mock RELD covering the §13
checklist and the RELD batch/cleanup cases; v18–v22 regression green.
